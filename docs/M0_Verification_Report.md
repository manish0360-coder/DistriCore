## 1. Executive Summary

### What M0 achieved

M0 built the floor the rest of DistriCore stands on, and **nothing that stands on it**.

Delivered: a reproducible containerised environment, an enforced architecture, an
authenticated identity model with OTP login, an append-only audit trail, structured
logging, a meaningful health endpoint, and a verification gate that can fail.

Five tables — `app_user`, `role`, `user_role`, `otp_request`, `audit_log`. Four
migrations. Six API endpoints. No products, customers, orders, invoices or stock exist.
That absence is the deliverable as much as the code is.

### Why it matters

Three things were established that become progressively more expensive to introduce later:

1. **A verification gate with teeth.** `make verify` runs a clean build, migration check,
   lint, architecture contracts, type check, the full suite behind a coverage floor, and a
   live health probe. It failed four times before it passed. A gate that has never failed
   is not a gate.
2. **Architecture enforced by CI, not by memory.** Three `import-linter` contracts make
   N-01 and N-02 mechanical. During M0 they caught a violation introduced by the Chief
   Systems Engineer — see §4.6. A rule only in a document is a suggestion.
3. **An audit trail that cannot be edited.** Immutability is enforced in Python, by a
   PostgreSQL trigger, and by an adversarial test that attacks both. Retrofitting a
   trustworthy audit is impossible: the history it would have recorded was never captured.

The first migration also carries the properties that `04` §17 classifies as irreversible:
identity primary keys, `timestamptz` throughout, no `tenant_id`, no hardcoded schema.
Those were correct on the first attempt because they were designed on paper first.

## 3. Architectural Decisions

Four ADRs accepted during M0. Three amend the frozen corpus; all were raised through the
§P.4 amendment process before any code depended on them.

### ADR-0001 — Record architecture decisions

**Necessary because** the reasoning behind a decision is lost within weeks otherwise, and
the decision is then either re-litigated or silently reversed by someone who never knew it
was deliberate.

**Long-term:** ADRs are immutable and superseded, never edited. The record survives
personnel change. Cost is friction per decision, which is the intent.

### ADR-0002 — Rename the `platform` module to `core`

**Necessary because** `platform` is a Python standard-library module. `manage.py` makes
`backend/` `sys.path[0]`, so `backend/platform/` shadows the stdlib for the whole process,
and Django imports `platform` in three places. The project would not have started, and the
traceback would have pointed at Django internals rather than the cause.

**Long-term:** none beyond the name. Amends `00` §4.1 and `03` §2.1. The lesson generalises:
module names are part of the design and deserve the same review as anything else.

### ADR-0003 — Exclude `django.contrib.admin`

**Necessary because** the admin writes directly through the ORM. It bypasses `services.py`
(N-01), so a stock adjustment made there would write no `stock_movement`, and a carelessly
registered `ModelAdmin` would allow `audit_log` rows to be edited (N-04).

**Long-term:** there is exactly one write path into the domain, and it is audited. Cost:
no ready-made CRUD screens; emergency data fixes go through service functions or a
documented `psql` runbook — which are the correct paths regardless. `django.contrib.auth`
remains, as `AUTH_USER_MODEL` requires it.

### ADR-0004 — §15.3 is a per-table checklist; stock columns bound to M2 by a CI gate

**Necessary because** `00` §20.1 asked M0 for a `0001_initial` carrying `location_id` and
`lot_id`, while §20.2 states M0 contains no stock. Django creates one initial migration
*per application*, so the requirement was ambiguous. Creating an empty `stock_movement`
in M0 would have violated C-2.

**Long-term:** the structural obligation now lives in `ops/check_structural_columns.py`,
executed by CI, rather than in a person's memory. It currently reports "not yet, expected
before M2" and will fail the M2 pull request if either column is absent. **This is the
single most consequential automated check in the repository** — E-06 rates the reversal
cost as High, against a cost today of two columns.

## 4. Bugs Found During Verification

Six defects, in the order they surfaced. Two were in code that had passed a human reading.

### 4.1 Container could not write tool caches

**Root cause.** `WORKDIR /app` creates the directory as root. Only `/app/backend`,
`/app/staticfiles` and `/srv/*` were chowned to the runtime user. But `/app` is the
*project root* — it holds `pyproject.toml`, and ruff, pytest, mypy and coverage all write
caches beside the config file, not inside `backend/`.

**Why it happened.** Ownership was granted to the directories that obviously held
*application* files, without asking where *tools* write.

**Fix.** `chown -R app:app /app`.

**Lesson.** The runtime user must own the tree it works in, not a subset of it. Setting
`RUFF_CACHE_DIR` would have made stage 4 pass and left the same defect for stages 6 and 7.

### 4.2 Dev tooling absent from the image

**Root cause.** The runtime stage installed production dependencies only. `ruff`, `pytest`,
`mypy` and `lint-imports` did not exist in the container the gate runs in.

**Why it happened.** The Dockerfile was written for production correctness; the
verification gate's own requirements were not traced through it.

**Fix.** A separate `dev` build stage carrying the dev extras, targeted by
`compose.dev.yml`. The production image still ships no test or lint tooling.

**Lesson.** A gate that runs inside the container is part of the container's contract.

### 4.3 The test suite ran against development settings

**Root cause.** `pyproject.toml` set `DJANGO_SETTINGS_MODULE = "config.settings.test"`, but
pytest-django gives the **environment variable precedence over the ini value**, and
`compose.dev.yml` exports `config.settings.dev`. The suite ran with live throttles, the
console SMS provider, Argon2 hashing and django-axes enabled.

**Why it happened.** Two mechanisms configured the same thing, and their precedence was
assumed rather than checked.

**Fix.** `--ds=config.settings.test` in `addopts`, which outranks the environment for any
invocation.

**Lesson.** When two mechanisms can set one value, pin the winner explicitly. Two of the
reported symptoms were consequences of this, not independent defects — reading the
`settings:` line in pytest's header first would have saved a cycle.

### 4.4 Invalid DRF throttle rates

**Root cause.** `"3/15min"` is not valid DRF. `SimpleRateThrottle.parse_rate` reads
`period[0]`, so `"15min"` yields `'1'` and raises `KeyError`. DRF supports only
`second|minute|hour|day`.

**Why it happened.** A rate was written to match the requirement text (`05` §13) without
checking that the library could express it.

**Fix.** Corrected to valid per-IP backstops. The security-meaningful per-phone limits were
never in DRF and were unaffected: OTP request throttling is a service rule, attempt capping
is a model field, login throttling is django-axes.

**Lesson.** A configuration string is code. It needs the same "does this actually parse"
scrutiny as an expression.

### 4.5 `verify_otp` rolled back its own attempt counter — **security defect**

**Root cause.** The function was decorated `@transaction.atomic` and did:

```
otp.attempt_count += 1
otp.save(...)
raise OtpInvalid(...)       # inside the same transaction
```

Raising inside an atomic block rolls the block back. **The increment was discarded on every
failed attempt.** `attempt_count` remained 0 permanently, the five-attempt cap in
FR-IAM-004 never engaged, and a six-digit OTP could be brute-forced without limit.

**Why it happened.** `@transaction.atomic` was applied as a default habit — "writes should
be atomic" — without asking which writes must survive a failure. The failure path was
treated as an error path rather than as a path that also records something.

**Fix.** An explicit transaction boundary. Failed attempts and code consumption are
committed inside the block; the rejection is raised **after** it closes. Two corrections
followed: `F("attempt_count") + 1` so concurrent guesses count independently, and a code is
consumed *before* the account-state check so a deactivated account cannot replay it.

**Lesson.** **Security counters must be committed on the path that fails.** More generally:
`@transaction.atomic` on a whole function is a decision about what is discarded on error,
not merely about consistency. Ask what must survive the exception.

This defect would not have been caught by code review — it reads correctly. It was caught
because a test asserted the counter's value after the exception.

### 4.6 Refresh rotation re-parsed the token it had just blacklisted

**Root cause.**

```
refresh.blacklist()
new_refresh = RefreshToken(token=str(refresh))   # decodes the blacklisted token
```

`BlacklistMixin.verify()` calls `check_blacklist()`, which rejects that jti. **Every valid
refresh token returned 401.**

**Why it happened.** The rotation sequence was inferred from the library's public names
rather than read from the library's own implementation.

**Fix.** SimpleJWT's `TokenRefreshSerializer.validate` mutates the token in place and never
re-parses: `blacklist()` → `set_jti()` → `set_exp()` → `set_iat()` → `outstand()`.
Implemented in that order.

**Lesson.** For a security-relevant library operation, read the library's own
implementation of it. Its tested path is the specification.

### 4.7 An architecture contract caught the Chief Systems Engineer

Fixing a mypy union-attr warning in `webadmin/views.py`, I imported `identity.models.User`
to `cast()` it. `lint-imports` **immediately broke the N-02 contract**: a delivery layer
importing a model.

The correct fix was `core.permissions.role_codes()`, reusing the narrowing `has_role()`
already performs — no cast, no model import, no `type: ignore`.

**Lesson.** This is the strongest single piece of evidence for §3's claim that architecture
must be enforced mechanically. The rule was written by the person who then broke it, in
service of satisfying a different tool, and would have passed self-review.

## 8. Lessons Learned

What an engineer joining tomorrow should know before writing a line of code.

**1. Read the documents in `docs/` first. They are the specification, not commentary.**
`00` is the constitution; where code and documents disagree, the documents win until
formally amended. Three of M0's four ADRs exist because a document was found to be wrong —
which is the process working, not failing.

**2. Nothing counts until it passes inside Docker.** `make verify` is the only authority.
It failed four times during M0 and each failure was a real defect. Local success proves the
code runs on a machine with your accumulated state.

**3. Design the irreversible parts on paper.** The first migration was correct on the first
attempt — identity keys, `timestamptz`, no `tenant_id`, no schema prefix — because `04` was
written and reviewed before any code existed. The two structural columns on
`stock_movement` are the same bet, and CI now enforces it.

**4. `@transaction.atomic` is a decision about what is discarded on error.** §4.5 is the
defect to internalise. Applying it by habit silently disabled a security control that read
correctly and passed human review. Ask what must survive the exception.

**5. Read the library's implementation for security-relevant operations.** §4.6. Inferring
a rotation sequence from public method names produced code that always failed. The
library's own tested path is the specification.

**6. Enforce architecture mechanically or not at all.** §4.7: the person who wrote N-02
broke it, in service of satisfying a type checker, and would have passed self-review.
`import-linter` caught it in seconds. A rule that lives only in a document is a suggestion.

**7. When two mechanisms configure one value, pin the winner.** §4.3 cost a full
verification cycle because `pyproject.toml` and an environment variable disagreed and the
precedence was assumed. Read the tool's own header output before diagnosing downstream.

**8. Write the test that asserts state *after* the exception.** The security defect in
§4.5 was invisible to review and to any happy-path test. It was caught only because a test
checked a counter's value after the call raised.

**9. Milestone boundaries are load-bearing.** M0 shipped no business features, and the
temptation to "add products while we're here" was the temptation to turn a verifiable
foundation into an unverifiable half-feature. Everything in §7's "not available" list stays
not available until M1 says otherwise.

**10. Cheap now, severe later — know which decisions are which.** Four of the five most
expensive decisions to reverse cost essentially nothing today: ledgers instead of mutable
balances, schema-agnostic migrations, immutable documents, two columns on a table that does
not exist yet. That asymmetry is the whole argument of `00`.
